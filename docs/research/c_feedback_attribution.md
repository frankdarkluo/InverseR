# C 反馈归因：模型能否利用仿真反馈

实际运行日期：2026-10-20 至 10-21。开发诊断，不是正式评价或模型排名。协议与授权见
[B0/B/C 协议](bc_protocol.md)；推理强度为 low（见 [B0 结果](b0_effort_probe.md)）。

## 1. 设计与执行

- 案例：[规划 pilot](planning_pilots.md) 的同 32 个布局（每 family 8 个）及其公共 goal，
  所以经典搜索的结果可以直接对照。
- 每局最多 8 次尝试，单杆、可在仿真中重置；三种条件：
  - **genuine：** 展示所提交动作的仿真结果（静止终态、接触事件、相对目标的误差）；
  - **shuffled：** 展示同布局上一个独立种子随机动作的仿真结果，但当作该次尝试的结果展示；
  - **reflection：** 不执行，只看到自己之前的动作。
- 三种条件共用同一个第 1 次尝试；若展示的结果报告已达到目标，该局结束；否则第 8 次的动作为
  最终提交，由独立的隐藏 judge 判分。
- 192/192 局完成；计费请求 1,388 个（共用首轮省去 64 个），用 4,799,654 token（上限 10M），
  按标价约 $10。agent 可见的仿真 737 次，隐藏 judge 1,308 次；0 个非法输出，无服务错误。
  完成后禁止 HTTP 与模拟器重跑，新增请求 0。

## 2. 结果

最终成功（1 球半径内、母球不落袋）：

| 模型 | genuine | shuffled | reflection |
| --- | ---: | ---: | ---: |
| GPT-5 | 6/32 [0.07, 0.36] | 0/32 [0, 0.11] | 0/32 [0, 0.11] |
| GPT-5-mini | 3/32 [0.02, 0.25] | 0/32 [0, 0.11] | 0/32 [0, 0.11] |

括号为 exact binomial 95% CI。按 source group 配对 bootstrap：

- GPT-5：genuine − shuffled ＝ genuine − reflection ＝ +18.8 个百分点，区间 [6.2, 31.2]；
  shuffled − reflection ＝ 0。
- GPT-5-mini：genuine − shuffled ＝ +9.4 个百分点，区间 [0, 21.9]。

其他读数：

- GPT-5 genuine 的 6 次成功出现在第 5–7 次尝试；按 family 是 free_roll 5/8、vertical 1/8、
  center 与 side 0。mini 的 3 次都在 free_roll。
- 最终尝试的误差中位数（GPT-5）：genuine 16.6r，shuffled 47.9r，reflection 50.9r。
- 按隐藏 judge 回看"历次尝试里最好的一次"，shuffled 也会偶然更接近目标（GPT-5 21.8r，
  mini 19.3r），但 agent 看到的是错误反馈，无法认出哪一次好，所以最终提交很远。这一指标用了
  agent 看不到的信息，只用于解释。

## 3. 与经典搜索对照（同 32 个案例）

| 方法 | 物理执行次数 | 成功 |
| --- | ---: | ---: |
| 几何直接计算 | 0 | 10/32 |
| 几何起点＋Powell | 8 | 10/32 |
| 几何起点＋Powell | 32 | 12/32 |
| 几何起点＋Powell | 128 | 14/32 |
| GPT-5 ＋ genuine 反馈 | ≤8 | 6/32 |
| GPT-5-mini ＋ genuine 反馈 | ≤8 | 3/32 |

信息不对称：模型看到完整终态和接触事件，Powell 只看到标量 loss；即便如此，模型在相同的
执行次数下仍不如几何起点加局部数值优化，也不如不搜索的几何直接计算。

## 4. 解读

- **模型确实利用了反馈内容。** genuine 明显好于 shuffled 和 reflection，而 shuffled 与
  reflection 都是 0：收益来自反馈里的真实信息，不是"多试几次"本身。
- **但作为规划器效率很低。** 成功几乎都在 free_roll；需要旋转的 family 基本没有解出。
  已知物理下的几何起点加数值优化在同样的执行次数下更好。
- 与 B1、B2 一起看：模型的盲测预测约等于直线近似，在 bank 里选不出正确候选，却能根据真实结果
  逐步修正动作；这更像"以执行结果为信号的试错"，而不是借助内部后果模型做规划。

## 5. 限制

- 32 个开发布局；每个请求只采样一次；最多 8 次尝试，只测了 low 推理强度。
- shuffled 的定义是"独立随机动作的结果"，不是跨案例置换。
- 经典搜索的结果来自规划 pilot（同一批案例和判分），不是这次运行里重新跑的。
